# Guardian Admin Console — خريطة التنفيذ المعتمدة

## مبدأ الصدق التشغيلي

تُظهر اللوحة حالة كل قدرة بأحد التصنيفات الثلاثة: **متاح ومتحقق**، أو **متاح في الكود لكن الربط الخارجي غير متحقق**، أو **معطل بسبب اعتماد أو صلاحية أو منفذ مفقود**. لا تُنشأ بيانات تجريبية أو نتائج نجاح اصطناعية، ولا تُفعّل mutations من الواجهة قبل تحقق backend من الهوية والصلاحية والاتصال والنتيجة.

## حدود التكامل

سيبقى Guardian Bot هو المالك لمسارات Telegram وRedis وPostgreSQL وCelery. تعمل اللوحة كـcontrol plane موثق عبر adapter/backend مقيد، ولا تنشئ مصدراً موازياً لإعدادات المجموعة أو جلسات الألعاب أو سجل moderation. إعدادات المجموعة تُقرأ وتكتب فقط عبر `group_settings` canonical، وسجل moderation والعضوية يقرأ من PostgreSQL عند توفر connector مصرح به، وحالة Redis وCelery تعرض كحالة تشغيلية لا كبديل لبيانات دائمة.

## الهوية والصلاحيات

تعتمد الواجهة على OAuth المدمج، مع حراسة tRPC server-side. ستكون صلاحية مدير الويب مستقلة عن إظهار الواجهة: كل إجراء حساس يتحقق من policy داخل backend، ثم من ارتباط المشرف بالمجموعة وقابلية التنفيذ. لا يمكن للواجهة تخطي سجل التدقيق، ولا يمنح role واجهة الويب البوت صلاحيات Telegram غير الموجودة فعلياً.

## الفحوص الدورية والتنبيهات

الفحوص deterministic وتشمل readiness والتنظيف والتقارير. ستستخدم HTTP scheduled handler محمياً لمسار `/api/scheduled/*`، مع idempotency وتسجيل نتيجة كل تشغيل. لا يُستخدم `setInterval` أو `node-cron` داخل process. إنشاء أو تعديل الجدول لا يتم قبل نشر الموقع؛ بعد تجهيز handler واختباره تحفظ checkpoint ثم يُطلب من المالك نشره، وبعدها فقط يمكن إنشاء الجدولة. التنبيهات الفورية ستستخدم قناة المالك المهيأة في المشروع عند تحقق condition مسجل، ولن تدعي تسليم alert إذا فشل الإرسال.

## خريطة أقسام الواجهة

| القسم | مصدر الحقيقة | نوع الوصول |
|---|---|---|
| ملخص التشغيل | probes حقيقية وhealth logs | قراءة محروسة |
| المجموعات والإعدادات | manager canonical | قراءة وكتابة محروسة ومدققة |
| moderation والأعضاء | PostgreSQL ونتائج Telegram المؤكدة | بحث وmutations محروسة |
| الحماية والمحتوى | settings وpatterns managers | إدارة محروسة ومدققة |
| الألعاب | GameSessionManager وRedis scoreboards | قراءة وإدارة داخل الحدود المملوكة |
| الميزات الاختيارية والمتجر | provider status وstate الحقيقي | status fail-closed وإدارة مشروطة |
| التدقيق والتشغيل | audit log وreadiness runs | بحث وتصدير منقح |
| التنبيهات والجداول | سجل alerts وHeartbeat jobs | تهيئة محروسة بعد النشر |

## استضافة الواجهة

تعمل لوحة الإدارة وفحوصها الدورية ضمن تطبيق WebDev المُدار. أما bot نفسه أو أي worker دائم يحتاج Python أو Docker أو provider runtime خاصاً فيبقى خارج عملية الواجهة؛ لا يُفترض أنه يعمل داخل عملية Node الخاصة باللوحة. إذا احتاج ربط مباشر دائماً مع bot في المستقبل، يجب تقييم استضافة دائمة مناسبة أو API موثق للبوت، بدلاً من محاكاة الاتصال من الواجهة.
