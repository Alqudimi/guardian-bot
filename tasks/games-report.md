# تقرير الجولة الرابعة: إصلاح منظومة الألعاب

## الملخص التنفيذي

تمت مراجعة منظومة الألعاب في Guardian Bot من مصدر التسجيل حتى handler الرسائل وRedis persistence. أظهر التدقيق أن جزءاً كبيراً من الأسماء المتاحة لم يكن ألعاباً مملوكة للبوت: عشرة modules كانت wrappers تفتح ألعاباً خارجية عبر `WebAppInfo`، وستة modules أخرى كانت placeholders لا تنفذ دورة لعب حقيقية. أزيلت هذه المكونات بدلاً من إبقائها كوظائف شكلية، ثم أُعيد بناء Mafia وChameleon داخل البوت مع الحفاظ على المعمارية الحالية.

> معيار قبول اللعبة في هذه الجولة هو أن يكون منطقها داخل المستودع، وأن تنفذ حالة لعب فعلية عبر Telegram messages وcallbacks، وأن تحفظ حالتها وتستعيدها، وأن تمتلك اختبارات تثبت التدفق لا مجرد وجود class أو زر.

## القرارات المنفذة

| المجال | القرار | النتيجة |
|---|---|---|
| الألعاب الخارجية | حذف `src/games/plugins/mini_apps/` وكل wrappers التي تعتمد على روابط خارجية | لا توجد `WebAppInfo` أو روابط ألعاب خارجية في مسارات الألعاب |
| الألعاب الوهمية | حذف `z5.py` و`conversational.py` و`worldwar.py` و`geosensei.py` و`codymaze.py` و`jigsaw.py` | لا يظهر اسم لعبة بلا تدفق فعلي في registry |
| التسجيل | حصر `register.py` في `mafia` و`chameleon` | registry واضح ومملوك للبوت |
| Mafia | إعادة بناء التسجيل، توزيع الأدوار، الليل، DM actions، النهار، التصويت، وحسم الفائز | لعبة نصية فعلية داخل Telegram |
| Chameleon | إعادة بناء اختيار الموضوع، توزيع الكلمة سراً، clues بالترتيب، التصويت، وحسم النتيجة | لعبة نصية فعلية داخل Telegram |
| الحالة | تقوية `GameSessionManager` مع TTL و`scan_iter` واستعادة legacy keys ومعالجة JSON الفاسد | استعادة أكثر أماناً واكتشاف الجلسات النشطة دون حجب event loop |
| routing | إضافة تحقق من callback payload واسم اللعبة، ودعم `chat_id` في DM callbacks | تقليل أخطاء التوجيه ومنع تشغيل اسم لعبة غير مسجل |
| الأوامر | تسجيل `/mafia_start` و`/cham_start` كـ `CommandHandler` صريحين | مسار رسمي واضح بجانب `/play mafia` و`/play chameleon` |

## تدفقات Mafia

تبدأ اللعبة بتسجيل اللاعبين داخل المجموعة، ويحدد المضيف بدء الجولة عندما يتوفر العدد المطلوب. عند الانتقال إلى الليل، توزع الأدوار فعلياً بين Mafia وDoctor وInspector وVillagers. ترسل أفعال Mafia وDoctor وInspector عبر رسائل خاصة، وتتحقق callbacks من اللاعب والهدف وحالة الدور قبل قبول الإجراء. بعد اكتمال الأفعال تنتقل اللعبة إلى النهار، وتجمع تصويت اللاعبين الأحياء، ثم تعلن الإقصاء وتفحص شروط فوز Mafia أو القرية قبل بدء ليلة جديدة.

تُحفظ حالة المضيف واللاعبين والأدوار والأهداف والتصويت والمرحلة والجولة في `get_game_state()`، ويمكن إعادة تحميلها عبر `load_game_state()` دون فقدان حالة اللعب الأساسية.

## تدفقات Chameleon

تبدأ اللعبة بتسجيل اللاعبين داخل المجموعة، ثم يختار النظام موضوعاً. يرسل البوت الموضوع والكلمة العادية سراً إلى اللاعبين غير المختارين، بينما يعرف اللاعب Chameleon أنه لا يملك الكلمة. يرسل كل لاعب clue فعلياً بالترتيب عبر المجموعة، وتنتقل اللعبة إلى التصويت بعد اكتمال clues. بعد جمع أصوات جميع اللاعبين تُحدد هوية المتهم والنتيجة، ثم تنتهي الجلسة وتُنظف الكلمة السرية من الحالة النهائية.

تتضمن الحالة المحفوظة موضوع الجولة، ترتيب الدور، index اللاعب الحالي، clues، الأصوات، وهوية Chameleon والنتيجة، مع استعادة قابلة للاختبار.

## الاختبارات ونتائج التحقق

تمت إعادة كتابة `tests/test_all_games.py` لتثبت ملكية الألعاب للبوت وتنفذ تدفقات اللعب بدلاً من اختبار wrappers أو placeholders. أضيف أيضاً اختبار تكاملي يستخدم Redis محلياً حقيقياً: ينشئ جلسة Mafia، يحفظها، يخلي الذاكرة، ثم يعيد تحميلها ويكتشفها عبر `scan_iter`. كما أضيف اختبار يثبت توجيه الأمرين الصريحين إلى اللعبة الصحيحة.

| التحقق | النتيجة |
|---|---:|
| `python -m compileall -q -f .` | ناجح |
| `pytest tests/test_all_games.py tests/test_hardening_regressions.py -q -W error` | 30 ناجحاً |
| `pytest tests/ -q -W error` | **166 ناجحاً** |
| فحص إشارات `WebAppInfo` و`MiniAppGame` وأسماء modules المحذوفة في `src` و`tests` و`README.md` | لا توجد إشارات |
| اختبار Redis الحقيقي لإعادة تحميل جلسة Mafia | ناجح |

## القيود المعروفة

تم تنفيذ التحقق داخل بيئة معزولة تملك Redis محلياً، لكنها لا تملك Telegram token حقيقياً ولا مجموعة Telegram مخصصة ولا PostgreSQL أو Docker daemon. لذلك تثبت الاختبارات منطق الحالة، serialization، routing، واستدعاءات Telegram عبر doubles محلية، كما تثبت Redis persistence عبر Redis حقيقي؛ لكنها لا تدعي تنفيذ Bot API حي أو التحقق من صلاحيات Telegram الفعلية أو التسليم الشبكي للرسائل الخاصة. يلزم قبل الإنتاج اختبار تشغيلي محدود على مجموعة مخصصة يملكها المشغل، مع token حقيقي و`DRY_RUN` مناسب وفق سياسة المشروع.

## خلاصة الاعتماد

منظومة الألعاب الآن أصغر وأكثر صدقاً وقابلية للصيانة: لا توجد ألعاب خارجية متخفية كميزات للبوت، ولا placeholders مسجلة على أنها وظائف مكتملة. توجد لعبتان داخليتان بتدفقات واضحة وحالة قابلة للاستعادة، وقد اجتازت suite الكاملة **166 اختباراً** مع تحويل التحذيرات إلى أخطاء.
